# 발표 멘트: Ghost-ALICE 비용·시간 절감 방안

대상 자료: [2026-11-23-cost-time-savings.pdf](2026-11-23-cost-time-savings.pdf) (19쪽). 1~18장을 발표하고, 19장(부록)은 질의응답 때 띄우는 예비 장표입니다. 전체 약 18분입니다.

시간이 모자라면 3·4장을 합쳐 1분으로 말하고, 11장은 "다음 네 장에서 봅니다"만 말하고 넘어가면 15분 안에 끝낼 수 있습니다.

## 1장. 표지와 전체 브리핑 (2분)

안녕하세요. 오늘은 Ghost-ALICE를 쓰면서 든 비용과 시간을 어떻게 줄일지 보고드리겠습니다. 11월 11일부터 23일까지 이 PC에서 실행한 세션 461개를 분석했습니다. 금액은 실제 청구액이 아니라 API 정가로 계산한 추정치입니다.

본론에 앞서 전체 내용을 요약하겠습니다.

첫째, 13일 동안 약 383달러와 26시간을 썼습니다. 비용의 83%는 답변을 쓰는 데가 아니라, 대화를 저장하고 다시 읽는 캐시에서 나왔습니다.

둘째, 원인은 네 가지입니다.

1. 대화가 길어질수록 답변이 비싸졌습니다.
2. 같은 벤치마크를 395번 돌렸습니다.
3. 예전 설치에서는 훅이 도구마다 약 5초씩 썼습니다.
4. 도구 호출 네 번 중 한 번은 기록과 검증을 위한 호출이었습니다.

셋째, 방안은 크게 둘입니다.

- 사용자 습관: 대화를 나누고, 오래 쉬었으면 새 대화를 열고, 모델을 고르고, 벤치마크를 줄입니다.
- 코드·운영: 훅을 가볍게 하고, 필요 없을 때는 끕니다.

이 중 훅 개선과 O13 수정은 이미 반영했습니다.

넷째, 모두 적용하면 비용은 약 145~170달러로 55~62% 줄고, 훅 대기는 6.1시간에서 약 2.2시간으로 줄어들 것으로 어림합니다. 가장 확실한 것은 벤치마크 축소(약 100달러)와 대화 나누기(약 77달러)입니다.

다섯째, 이 숫자들은 독립 검증자 네 명이 확인했고, 틀린 곳 네 군데는 고쳤습니다.

이제 하나씩 보겠습니다.

## 2장. 한눈에 보기 (50초)

숫자 네 개만 기억해 주세요. 383달러, 26.3시간, 거버넌스 호출 26%, Stop 차단 441번입니다.

원인 쪽에서는 세 가지가 큽니다. 캐시가 비용의 83%입니다. 세션 하나가 전체의 25%를 썼습니다. 벤치마크가 35%를 썼습니다.

오른쪽 결론은 방금 말씀드린 그대로입니다. 약 55~62%를 절감할 수 있고, 그중 단단한 두 가지는 벤치마크 축소와 대화 나누기입니다.

## 3장. 무엇을 쟀나 (50초)

대화 기록과 훅 기록을 세션 단위로 모았습니다.

- 직접 작업한 대화: 12개, 239달러
- 자동 실행 테스트: 449개, 144달러

비용은 토큰 수에 API 정가를 곱했습니다. 시간은 기록 사이 간격이 5분 이하인 구간만 더했습니다. 한계도 있습니다. PC 1대, 사용자 1명 기준이고, 하위 에이전트 토큰은 빠졌습니다.

## 4장. 돈은 어디로 갔나 (50초)

답변을 쓰는 출력 비용은 17%입니다. 대화를 저장하는 캐시 쓰기가 46%, 다시 읽는 캐시 읽기가 36%입니다.

모델은 답변할 때마다 지금까지의 대화를 다시 읽습니다. 그래서 대화가 길수록 같은 질문도 비싸집니다. 답변 하나 단가는 fable이 opus보다 약 6배 비쌌습니다.

## 5장. 원인 1: 긴 대화 (1분)

대화 안에서 1~10번째 답변은 0.068달러였고, 41번째 이후 답변은 0.327달러였습니다.

가장 비싼 질문은 14.91달러였습니다. 6.7일 쉬었다가 긴 대화를 이어 간 첫 질문이었고, 그중 14.11달러가 캐시를 다시 쓰는 데 들었습니다.

다만 이것은 상관관계입니다. 세션 하나가 직접 작업 비용의 41%라 평균을 크게 좌우합니다. 지금 다시 계산하면 4.8배가 아니라 약 3.7배입니다.

## 6장. 원인 2: 반복 실행 (50초)

같은 벤치마크를 395번 돌려 134달러, 약 6.7시간을 썼습니다.

그런데 395번 중 392번이 같은 이유로 차단되었습니다. 결과가 이렇게 쏠려 있으면 적은 횟수로도 같은 결론이 나옵니다.

100회로 줄였다면 약 100달러와 5시간을 아꼈을 것입니다. 100회는 예시이고, 필요한 횟수는 확인하려는 차이의 크기로 정해야 합니다.

## 7장. 원인 3: 훅 대기 (50초)

예전 설치에서는 도구를 한 번 쓸 때마다 훅이 4.93초를 썼고, 합계는 6.1시간입니다.

main 계열에서는 도구당 약 1.8초로 줄었고, 재설치 뒤 실제로 재 보니 1.57초였습니다. 처음에 보고한 1.52초는 거부된 훅의 시간이 빠진 과소 추정이었습니다.

## 8장. 원인 4: 거버넌스 부담 (50초)

Stop 차단 441번 중 97.5%가 응답 경로 미등록 때문이었습니다.

도구 호출이 전부 거버넌스였던 답변은 1,042개, 57달러입니다. 이 금액이 이 방안으로 줄일 수 있는 상한입니다.

차단은 모두 예전 설치에서 났고, main 계열은 일반 답변에 응답 경로를 요구하지 않습니다.

## 9장. O13 발견과 조치 (1분)

설치를 바꾼 뒤 입력을 기록하는 훅이 66번 모두 거부되고 있었습니다. 원인은 Windows 경로를 비교할 때 슬래시와 역슬래시를 다르게 본 것이었습니다.

고쳐서 설치한 뒤로 거부는 0번입니다. 다만 그동안 진단 도구 doctor는 계속 "ok"를 보고했습니다.

수정 뒤 일상 질문 6문항으로 다시 재 보니 차단은 0.44에서 0으로 줄었습니다. 날씨 질문에서는 상태 문장이 답에 섞였고, 이것을 O14로 기록했습니다.

## 11장. 모두 적용한다는 것 (50초)

"모두 적용"은 여덟 가지를 함께 한다는 뜻입니다.

- 가~라 넷은 사용자 습관입니다. 대화 나누기, 쉬었다 이어 가지 않기, 모델 고르기, 벤치마크 줄이기입니다.
- 마·바·사 셋은 이미 반영했습니다. O13 수정, main 계열 Core, io-trace 비동기입니다.
- '아'는 다시 재는 일로, 일부만 끝났습니다.

다음 네 장에서 각각을 무엇으로, 어떻게 하는지 보여 드리겠습니다.

## 12장. 절감 방법 1: 사용자 습관 (1분 10초)

- 대화가 20질문 안팎이 되면 compact-handoff skill로 요약을 만들고, 새 세션 첫 질문에 붙입니다.
- 꼭 같은 대화를 이어야 하면 `/compact`로 이전 내용을 요약으로 줄입니다.
- 한 시간 넘게 쉬었다면 캐시가 사라져 대화 전체를 다시 저장합니다. 그러니 요약을 가지고 새 대화를 엽니다.
- 모델은 시작할 때 `/model`로 정합니다. 도중에 바꾸면 캐시를 새로 씁니다.
- 벤치마크는 횟수를 먼저 정합니다. 수정 확인은 `run_daily_test.py --ids`로 문제 문항만 돌립니다.

## 13장. 절감 방법 2: 코드와 운영 (1분)

이미 반영된 것:

- main 계열 Core로 Autopilot 훅을 뺐습니다.
- io-trace는 `async: true`로 기다리지 않게 했습니다.
- Stop 규칙을 바꿨습니다.
- O13 경로 비교를 고쳤습니다.

남은 일은 거버넌스 전용 답변 줄이기이고, O14 이슈가 후보입니다.

효과를 재는 도구는 `run_daily_test.py`, `full_execution_report.py`, `install.cmd --doctor`입니다. doctor가 O13을 잡지 못했으니, 설치 뒤에는 훅 기록의 종료 코드도 함께 확인해야 합니다.

## 14장. 훅 사용 여부 1: 훅별 (1분 10초)

훅 하나하나를 보겠습니다.

- 도구마다 도는 훅 세 개가 시간을 가장 많이 씁니다. tool-checkpoint는 1.44초에서 0.22초로 줄었습니다. Autopilot 준비 훅은 아예 빠졌습니다. io-trace는 비동기라 이제 기다리지 않습니다.
- 질문이나 세션마다 한 번 도는 훅은 1초 안팎입니다. session-intent, SessionStart, completion이 여기에 해당합니다.
- 다만 session-intent를 끄면 원장 기능 전체가 멈춥니다.

그래서 결론은 이렇습니다. 남은 훅은 대부분 켜 두고, pending-merge 하나만 필요한지 검토합니다.

## 15장. 훅 사용 여부 2: 켬과 끔 (1분 10초)

Ghost-ALICE 전체를 끄면 일상 질문 비용이 약 3.6분의 1이 됩니다. 6문항 기준으로 켬은 1.45달러에 164초, 끔은 0.40달러에 84초였습니다.

끄는 방법은 다섯 가지입니다.

- 이번 실행만 전부 끄기: `claude --safe-mode`
- 이번 실행만 훅 끄기: `--settings`로 `disableAllHooks`를 true로 지정
- 계속 끄기: settings 파일에 `disableAllHooks`
- 훅 하나만 끄기: settings.json에서 그 항목을 지웁니다.
- visibility 프로필은 화면 표시만 바꾸고 시간은 줄이지 않습니다.

권장은 이렇습니다. 일상 질문과 단순 조회는 끄고, 코드 수정과 검증 작업은 켭니다. 주의할 점이 있습니다. 전체를 끄면 Langfuse 전송과 공유 기록 읽기도 함께 꺼집니다.

## 16장. 모두 적용하면 (1분)

비용은 383달러에서 약 145~170달러로, 훅 대기는 6.1시간에서 약 2.2시간으로 줄어들 것으로 어림합니다.

직접 작업 239달러는 이렇게 계산했습니다.

1. 대화 나누기로 162달러
2. 거버넌스 감소로 144달러
3. 모델 교체로 127달러
4. 재저장 회피로 107달러

자동 실행 144달러는 벤치마크 축소로 약 38~43달러가 됩니다.

80%, 70%, 20달러 세 가지는 측정하지 않은 가정입니다. 4단계는 1단계와 겹칠 수 있어서 직접 작업은 107~127달러 범위로 봅니다.

## 17장. 이 숫자를 믿어도 되나 (50초)

검증자 네 명이 서로의 결과를 보지 않고 따로 확인했습니다. 기본 집계와 단가는 모두 맞았습니다.

틀린 곳은 고쳤습니다.

- 날짜별 벤치마크 횟수
- 거부 합계: 73이 아니라 79
- sk-port 변경 규모
- 훅 시간: 1.52초가 아니라 약 1.8초
- 절감 범위: 55~62%로 넓힘

한계도 있습니다. Codex와 Gemini는 로그인 문제로 실행하지 못해서 검증자가 모두 Claude 모델입니다.

## 18장. 제안과 마무리 (1분)

정리하겠습니다.

- 오늘부터 바꿀 습관: 단계가 끝나면 새 대화를 엽니다. 한 시간 넘게 쉬었으면 새 대화를 엽니다. 모델은 시작할 때 정합니다. 일상 질문은 Ghost-ALICE를 끄고 합니다.
- 다음 운영: 벤치마크는 문제 문항 위주로 돌립니다. 대화형 측정을 해서 오늘의 어림값을 실측으로 바꾸겠습니다.
- 팀이 정할 것: 벤치마크 반복 기준, 대화형 측정 질문 목록, 그리고 O14와 doctor 경고 보강을 이슈로 올릴지입니다.

가정과 자료 위치는 부록에 있습니다. 질문 받겠습니다. 감사합니다.
