- 기준 버전: `test-baseline-2026-11-16` (Core `c6019ac`, Autopilot `v0.5.1` `2075768`). 시험에는 `core/main` `450e4b3`(A)과 `kyu/core-review-lite` `15b6e2b`(B)을 썼습니다.
- 확인 환경: Windows 11 Pro, Git Bash와 PowerShell 7, Python 3.14.7, Claude Code 2.1.330(시험 중 업데이트 없음), 모델은 Sonnet 5.5와 Haiku 5.5
- 관련 링크: 안내서 [`TESTING.md`](../kyu/evidence/2026-11-24/TESTING.md), kyu 성능 보고서 [`2026-11-24-performance-measurement.md`](../kyu/2026-11-24-performance-measurement.md)

## 1. 목표

안내서의 질문은 "B(kyu 방식)가 응답을 검토해서 A(JY 방식)가 틀린 답을 고치는가"입니다. 함정이 있는 케이스 10개(`testbed2`)를 3회씩, 두 모델에서 A와 B를 번갈아 돌렸습니다. 기준은 안내서 6절에 시험 전에 정해 두었습니다.

## 2. 한 일

1. `kyu` 저장소를 `~/ga-test/src/team`에 복제하고, `core-a`(`core/main`)와 `core-b`(`kyu/core-review-lite`) 워크트리를 만들었습니다. 두 곳 모두 시험 전용 패치 `0-test-only-sdk-origin.patch`를 같은 방식으로 적용했습니다.
2. `install_arm.ps1`로 시험용 홈 두 개(`home-base`, `home-imp`)에 설치하고 `Verification ok`를 확인했습니다. 실제 설치본(`~/.claude`, `~/.ghost-alice`)은 바꾸지 않았고, 설치 전후 파일 지문이 같음을 확인했습니다.
3. Sonnet으로 `run_batch.py --arms sa:base sb:imp --repeats 3 --suite testbed2 --model sonnet`을 60회 돌렸습니다. 처음 10회는 어제 실행했고, 나머지 50회는 오늘 이어서 실행했습니다.
4. Haiku로 `run_batch.py --arms ha:base hb:imp --repeats 3 --suite testbed2 --model haiku`를 60회 돌렸습니다.
5. `aggregate.py`로 집계하고, 모든 실행에서 함정 값 문자열 검사와 "첫 답(`blocked_drafts`)과 최종 답(`answers`)이 같은지" 검사를 손으로 다시 했습니다.

### 3-3. 손 확인

- 함정 값 문자열이 답에 들어간 실행이 여러 개 있었습니다. 열어 본 답(Sonnet: sb T3 1회차, sa H1 1회차, sa H4 1회차, sb T4 3회차 / Haiku: hb H1 2회차, hb H4 1회차, hb T3 1회차, ha T5 3회차)은 모두 함정 값을 틀린 값으로 짚거나, 다른 항목과 구분해서 설명한 것이었습니다. 다만 `hb` T2 1회차의 "5번"은 열어 보지 않아 오답 여부를 확인하지 못했습니다.
- Haiku B의 검토가 바꾼 8건 중 최종 답이 달라진 것은 없었습니다. 대부분 "검토가 통과하지 못했다"는 안내가 붙었고, `hb` H1 1회차는 앞선 잘못된 중간 합계를 정정한 것으로 보입니다.
- Sonnet B의 검토가 바꾼 한 건(sb T3 1회차)도 첫 답이 이미 맞았고, 최종 답에는 "검토에서 확인되지 않아 `unsupported`" 문구만 추가됐습니다.

## 5. 확인하지 못한 것

- 시험 대상은 `testbed2` 10개 케이스입니다. 두 모델 모두 대부분 맞혔기 때문에, B의 검토가 효과를 보일 만큼 어려운 조건은 아니었습니다. A가 실제로 많이 틀리는 조건에서는 결과가 다를 수 있습니다.
- 채점은 키워드 검사로 했습니다. 키워드가 맞는 답 중에도 잘못된 설명이 있을 수 있고, 손 확인은 실행 일부에만 했습니다.
- 한 PC, 하루의 측정입니다. 금액 절대값은 PC와 날짜에 따라 달라지므로, 다른 PC 결과와는 직접 비교하지 않았습니다.
- Autopilot 확인(선택 항목: 완료 조건이 있는 케이스를 B에서 3회 돌리기)은 하지 않았습니다.
- B의 검토가 응답을 바꾼 것이 실제로 정확도를 높였는지는 확인하지 못했습니다. A가 틀린 실행이 없어서 비교할 기준이 없었습니다.
