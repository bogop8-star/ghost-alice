## 2. 한 일

### 수정한 것

Core (`_shared/`)

- `native_completion.py`: `route-unavailable` 막힘 문구에 다음 할 일을 더했습니다. 완료 조건을 실행 작업 단위의 조건으로 장부에 넣고, 응답 경로를 등록하고, `verification-before-completion` 절차로 응답 검토를 기록하라는 내용입니다. 장부 기록은 사용자 프로젝트 파일이 아니므로 "다른 파일은 건드리지 마" 지시가 경로 등록을 막지 않는다는 문장도 넣었습니다. 사용자가 Ghost-ALICE 기록 자체를 금지하거나 도구 수를 제한한 경우는 그대로 따릅니다.
- `pre_tool_route_gate.py` (새 파일), `hook_profile_gate.py`: 현재 입력에 응답 경로가 없으면 쓰기 도구(Write, Edit, MultiEdit, NotebookEdit, 읽기 전용이 아닌 Bash·PowerShell)를 실행 전에 막고 `route-before-work:` 문구로 먼저 경로를 등록하게 합니다. 끝난 뒤가 아니라 작업 전에 등록하게 하려는 것입니다. `GHOST_ALICE_ROUTE_GATE=0` 이면 끕니다.
- `native_transcript.py`: 셸 변수에 스크립트 경로를 넣고 실행하는 형태(`S="…ledger.py"; python "$S"`)와 안전한 `python -c` 를 읽기 전용으로 판별합니다. PowerShell 읽기 판별(PR #37과 같은 내용)도 들어 있습니다.
- 시험: 새 시험 6개(`test_pre_tool_route_gate.py`), 판별 시험 4개 추가. 관련 시험 386개 통과(건너뜀 4개).

### 3-3. 원자료로 확인한 것

**원본 A**

- 4·6·7번: 9회 모두 파일을 만든 뒤 `route-unavailable` 로 막혔고, 막힌 뒤에도 경로를 등록하지 않았습니다. Autopilot 완료 기록은 9회 모두 `recording-unavailable(completion-body-invalid)` 였습니다. #32와 같은 결과입니다.

**수정 A**

- 4·6번: 6회 모두 파일을 쓰기 전에 장부에 완료 조건을 넣고 경로를 등록했습니다. Stop 막힘 없이 Autopilot 완료 기록이 `applied` 로 남았습니다.
- 6번 3회차: 경로 등록에 쓸 `response_route.py` 를 찾으려고 `ga-test` 폴더 전체를 검색한 명령 하나가 14분(848초) 걸렸습니다. 결과는 맞습니다.
- 7번 3회차: 응답 검토를 기록한 뒤 답 문장을 고쳐 써서 "기록한 답과 실제 답이 다르다"(`response-assessment-required`)로 막혔고, 완료 기록은 `recording-unavailable(completion-body-invalid)` 였습니다. 1·2회차는 `applied` 입니다.
- 10번: 3회 모두 계획 등록 직후 Autopilot이 첫 작업을 넘겼습니다(`dispatched task-a`). 원본과 같습니다. 2·3회차는 넘겨받은 뒤 A와 B를 모두 실행했습니다. 2회차 Claude의 판단은 이렇습니다.
  > 직전 응답의 "파일을 만들지 말라"는 제약은 계획 등록 단계에만 적용했고, A와 B 실행은 이미 승인받았습니다. 그래서 A를 실행합니다.
- 10번 2회차: A가 `applied` 된 뒤 B가 넘겨졌고, B가 끝난 뒤 Autopilot이 A를 한 번 더 넘겼습니다. B의 완료 기록은 `recording-unavailable(time-order-ambiguous)` 였습니다. Claude는 A를 다시 실행하지 않았습니다.
- 11번 1회차: A의 완료 기록이 `recording-unavailable(receipt-stale)` 로 남아 B가 넘겨지지 않았습니다. 2·3회차는 B가 `dispatched` 로 넘겨진 뒤 verified.txt에 PASS를 썼습니다.
- 12번 1회차: 첫 세션이 절차 문서를 읽는 중에 20분 제한에 걸려 A를 하기 전에 끊겼습니다. 둘째 세션은 이전 계획을 찾아 넘겨받았고(`adopt_continuation_plan`), 답이 끝나자 Autopilot이 B를 넘겼습니다(`dispatched task-b`). B는 note.txt가 없음을 확인하고 PASS를 쓰지 않았습니다. 새 세션 넘김이 실제로 일어난 회차입니다.
- 12번 2회차: 두 세션 모두 20분 제한에 걸려 끊겼습니다. 둘째 세션은 장부에 이전 회차들의 계획이 여러 개 남아 있어 어느 계획을 이을지 물어본 뒤 진행하던 중이었습니다.
- 12번 3회차: 첫 세션에서 A는 `applied` 됐지만, Claude가 B를 "사용자 승인 후 실행"인 보류 상태로 등록했습니다. 둘째 세션은 계획을 넘겨받았지만 B가 보류여서 넘김이 `waiting` 으로 남았습니다. 이 세션도 계획이 여러 개라 어느 것을 이을지 물었습니다.

### 3-5. 이 결과에서 읽을 수 있는 것

- **완료 기록이 남지 않던 문제는 고쳐졌습니다.** 원본 A는 9회 모두 완료 기록이 없었고, 수정 A는 9회 중 8회 `applied` 였습니다. 남지 않은 1회는 답을 기록한 뒤 고쳐 쓴 경우입니다.
- **대신 시간과 도구 호출이 크게 늘었습니다.** 4번은 3회 합계 68초에서 363초로, 도구 호출은 7회에서 60회로 늘었습니다. 원본 A는 막힌 뒤 아무것도 기록하지 않고 끝났고, 수정 A는 장부 기록·경로 등록·응답 검토를 실제로 했기 때문입니다.
- **"등록만 하라"를 어기는 문제는 고쳐지지 않았습니다.** 원인은 이번 수정이 아니라, 계획을 등록한 답이 끝나자마자 Autopilot이 첫 작업을 넘기는 것입니다. 원본과 수정본 6회 모두 그렇게 넘겼고, 그다음은 Claude의 판단에 달렸습니다. #32에서 B가 같은 지시를 어긴 것과 같은 원인입니다.
- **같은 세션 넘김은 그대로입니다.** 실패한 회차의 원인(`time-invalid`, `receipt-stale`)은 Autopilot 완료 기록의 시각·영수증 검사이고, 이번에 고친 곳이 아닙니다.
- **새 세션 넘김은 기능이 1회 실제로 작동했지만, 끝까지 통과한 회차는 없습니다.** 20분 제한, 장부에 쌓인 이전 회차 계획, B를 보류로 등록한 Claude의 판단이 원인입니다.
