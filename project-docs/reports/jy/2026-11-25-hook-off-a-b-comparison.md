# 훅 끔·JY 방식(A)·kyu 방식(B) 대화형 비교: 지시 12개

Nov 25, 2026 · jy

- 기준 버전: `test-baseline-2026-11-16` 과 다릅니다. A는 Core `core/main` `450e4b3`(JY 방식), B는 Core `kyu/core-review-lite` `15b6e2b`(kyu 방식, 닫힌 PR #13)입니다. 둘 다 Autopilot `v0.5.1` `2075768` 을 함께 설치했습니다. 훅 끔은 Ghost-ALICE를 설치하지 않은 빈 설정 폴더입니다.
- 확인 환경: Windows 11 Pro 25H2 (10.0.26200.9974, 한국어), PowerShell 7.6.10, Python 3.14.4, Git 2.55.0, Claude Code CLI 2.1.310 (터미널 대화형, 모델 `claude-opus-5-5`, effort `medium`, 권한 모드 `auto`)
- 관련 링크: [A·B 비교 시험 안내](../kyu/evidence/2026-11-24/TESTING.md), [kyu 성능 측정 보고서](../kyu/2026-11-24-performance-measurement.md), [훅 끔·켬·수정 후 비교 테스트](2026-11-24-hook-on-off-fix-test.md), A·B 비용 비교 보고서 `2026-11-24-ab-cost-comparison.md` (별도 PR)

## 1. 목표

A와 B 중 무엇을 팀 기본으로 둘지 판단할 근거를, 자동 실행(`claude -p`)이 아닌 대화형 입력으로 다시 확인합니다. 같은 지시 12개를 훅 끔, A, B 세 환경에서 돌려 다음을 봅니다.

- 답과 파일이 맞는가.
- Stop 훅이 언제, 어떤 사유로 답을 막는가.
- 응답 검토가 틀린 답을 실제로 고치는가.
- 완료 조건이 있는 작업에서 Autopilot 완료 기록이 남는가.
- Autopilot이 승인된 다음 작업을 넘겨주는가.

지시마다 확인 기준을 두고, 환경별 결과가 그 기준을 충족했는지 적습니다.

## 2. 한 일

- 터미널에서 `claude` 를 대화형으로 띄우고 입력을 실제 키 입력으로 넣는 실행기로 돌렸습니다. 2026-11-24 훅 끔·켬·수정 후 비교 때와 같은 방식입니다.
- 한 환경에서 지시 12개를 모두 돌린 뒤 다음 환경으로 넘어갔습니다. 순서는 훅 끔(2026-11-24 23:23~23:34), A(2026-11-25 00:03~00:46), B(2026-11-25 00:58~01:41)입니다.
- 첫 지시(도구 없는 질문)만 1회, 나머지 11개는 3회씩 돌렸습니다. 환경마다 34회, 모두 102회입니다.
- 환경을 이렇게 나눴습니다.
  - 훅 끔: Ghost-ALICE 지시문·스킬·훅이 하나도 없는 빈 설정 폴더. 로그인 정보만 넣었습니다.
  - A, B: A·B 비용 비교 때 후보별로 따로 설치해 둔 시험용 홈을 그대로 썼습니다. 실제 설치본은 건드리지 않았습니다.
  - 작업 폴더는 환경마다 따로 두고, 회차마다 비운 뒤 시험 자료를 새로 넣었습니다. 시험 자료는 kyu 시험 키트의 `testbed/fixture` 와 `testbed2` 의 `sales.csv`, `events.csv` 입니다(README 17줄, 첫 제목 "테스트용 문서").
  - A와 B는 그 환경의 Core, Autopilot, 설치 폴더를 `--add-dir` 로 작업 폴더에 포함했습니다. 시험 안의 Claude가 절차 문서를 읽을 때 "작업 폴더 밖 읽기" 질문 창이 떠서 멈추는 것을 막기 위해서입니다.
- 시작 전에 세 환경에 "컨텍스트에 들어온 지시문 파일과 스킬 이름을 적어라"를 한 번씩 넣어 환경을 확인했습니다. 훅 끔은 지시문과 Ghost-ALICE 스킬이 없었고, A와 B는 각자 설치 폴더의 지시문 하나와 Ghost-ALICE 스킬만 있었습니다.
- 회차마다 답, 도구 호출, 파일 상태, 훅 기록(`strict-hook-output.jsonl`), 장부의 완료 조건과 응답 경로를 모아 판정했습니다. 판정 뒤 원자료를 다시 읽어 3-3절의 내용을 확인했습니다.

환경을 잘못 잡아 결과를 버린 실행이 있습니다. 아래 실행은 결과에 넣지 않았습니다.

### 3-3. 원자료로 확인한 것

**A**

- 3번: 세 회차 모두 받은 명령을 그대로 실행했고 `route-unavailable` 로 막혔습니다. 같은 명령을 A(`450e4b3`)의 읽기 전용 판별 함수 `_read_only_call` 에 넣으면 작업(읽기 전용 아님)으로 판정됩니다.
- 8번: 세 회차 모두 막히기 전 초안의 첫 줄이 이미 "합계는 9,815.10"이었습니다. 10,815.10은 "TOTAL 줄 값이 계산과 1,000 차이 난다"는 설명에만 나왔습니다. 막힘은 계산을 셸 명령으로 해서 읽기 전용 판별을 통과하지 못한 것입니다.
- 6·7번: 6회 모두 막힌 뒤에도 응답 경로가 등록되지 않았습니다(경로 읽기 결과 없음, 오류 없음). 7번의 3회는 장부에 완료 조건 1개가 있었지만 경로가 없어 Autopilot 완료 기록이 `recording-unavailable(completion-body-invalid)` 로 남았습니다.
- 11번: 2·3회차는 둘째 작업이 넘겨진 기록(`dispatched`)이 없습니다. 2회차는 첫 작업의 완료 기록(`applied`)도 없습니다.
- 12번: 3회 모두 첫 세션에서 계획 등록과 첫 작업의 `applied` 까지는 됐습니다. 둘째 세션에서 둘째 작업이 넘겨진 기록은 한 번도 없습니다. 1·3회차는 넘겨받지 않은 채 verified.txt에 PASS를 직접 썼고, 2회차는 쓰지 않았습니다.

**B**

- 8·9번: 6회 모두 막히기 전 초안부터 정답이었습니다. 검토가 오답을 고친 회차는 없습니다.
- 9번: 3회 모두 첫 검토가 "근거 문구가 도구 결과에 그대로 없다"로 거절됐고, 고쳐 낸 두 번째 검토가 통과했습니다.
- 8번 2회차: 검토가 "east 11건을 뺐다"는 문장을 근거 부족(unsupported)으로 판정했습니다. 최종 답의 합계는 정답입니다.
- 6번: 3회 모두 장부의 완료 조건이 0개였고, Core가 작업 단위 0개짜리 경로를 자동 등록했습니다. 목적은 1회차가 `explanation`, 2·3회차가 `execution` 이었습니다. Autopilot 완료 기록은 `skipped(no-current-execution)` 또는 `recording-unavailable(completion-body-invalid)` 였습니다.
- 7번: 3회 모두 장부에 완료 조건 1개가 있었고 `route-unavailable` 로 막혔습니다. 완료 조건이 장부에 있을 때 자동 등록을 건너뛰는 분기가 작동한 것입니다.
