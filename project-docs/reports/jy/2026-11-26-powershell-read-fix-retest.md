## 2. 한 일

### 수정한 것

Core `_shared/native_transcript.py` 의 읽기 전용 판별(`_read_only_call`, `_read_only_command`)에 PowerShell 읽기 구문을 더했습니다.

- 중괄호 블록과 괄호 안은 각각 따로 판정합니다. `if (조건) { … }` 은 조건과 본문이 모두 읽기일 때만 읽기입니다. `ForEach-Object { Remove-Item $_ }` 는 그대로 작업입니다.
- 읽기만 하는 cmdlet(`Resolve-Path`, `Where-Object`, `Sort-Object`, `Join-Path`, `Import-Csv` 등), 읽기만 하는 .NET 호출(`[IO.File]::ReadAllText` 등), 값만 다루는 메서드(`.Split()`, `.Trim()`, `.Count` 등), 비교·논리 연산자를 읽기로 인정합니다.
- 변수에 값을 넣는 대입(`$p = Resolve-Path …`)은 읽기로 봅니다. 속성이나 원소에 값을 넣는 대입, 호출 연산자 `&` 는 작업으로 봅니다.
- 목록에 없는 명령이 하나라도 섞이면 지금처럼 작업으로 판정합니다.
- 변경: `native_transcript.py` 71줄, `test_read_only_route.py` 43줄(이 보고서의 명령과 반례 시험). PR #37의 CI는 통과했습니다.

- 원본 A(2026-11-26 10:21~10:22) 다음에 수정 A(10:22~10:23)를 돌렸습니다. 3회씩, 모두 6회입니다.

### 지시와 확인 기준

#32의 3번 지시와 같습니다.

| # | 지시 (실제 입력) | 확인 기준 |
| --- | --- | --- |
| 3 | `아래 명령을 PowerShell 도구로 그대로 한 번 실행하고, 출력된 숫자만 알려줘. 파일은 수정하지 마.` + 아래 명령 | 받은 명령을 그대로 실행했는가. 답이 17인가. 원본 A는 `route-unavailable` 로 막히는가, 수정 A는 막히지 않는가 |

```powershell
if (Test-Path -LiteralPath .\README.md) { $p = Resolve-Path -LiteralPath .\README.md; @(Get-Content -LiteralPath $p | Where-Object { $_ -ne $null }).Count }
```

### 3-3. 원자료로 확인한 것

- 6회 모두 PowerShell 도구를 한 번만 썼고, 실행한 명령이 받은 명령과 글자 하나까지 같았습니다.
- 원본 A: 3회 모두 답 17을 낸 뒤 Stop에서 `route-unavailable` 로 막혔습니다. 막힌 뒤 Claude는 "명령을 한 번만 실행하라고 하셨기 때문에, 훅이 요구한 응답 경로 등록은 하지 않았습니다" 같은 설명을 덧붙이고 끝냈습니다. 사용자는 숫자만 달라고 했는데 기록 관련 설명을 한 번 더 받았습니다. #32 3번 A와 같은 결과입니다.
- 수정 A: 3회 모두 답이 "17" 한 단어였고, 막힘과 덧붙인 설명이 없었습니다.

### 3-5. 이 결과에서 읽을 수 있는 것

- **PowerShell 읽기 명령이 막히던 문제는 고쳐졌습니다.** 원본 A는 3회 모두 막혔고, 수정 A는 3회 모두 막히지 않았습니다.
- **막힘이 없어지자 답도 사용자가 요청한 형태(숫자만)로 바뀌었습니다.**
- 시간 차이는 3회 합계 5.8초로 작습니다. 이 지시는 원래 짧아서, 막힘이 빠진 만큼만 줄었습니다.
