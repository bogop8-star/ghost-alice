## 7. 새로 확인한 문제: 설치 전환 뒤 입력 기록 훅이 거부됨 (O13)

- 관찰: main 계열 설치 뒤, 종료 코드 126(훅 명령 거부)이 73번 기록됐습니다. 내역은 UserPromptSubmit의 session-intent 56번, SessionStart의 session-receipt 12번과 session-start 11번입니다. 거부 문구는 `hook command rejected: inner ledger root conflicts with trusted binding`입니다. 설치 전환 뒤 session-intent 훅은 56번 실행돼 56번 모두 거부됐고, 정상 종료는 0번입니다. 첫 거부는 11-16 15:07(KST), 마지막은 11-23 11:09입니다.
- 원인 코드: `_shared/hook_profile_gate.py`가 훅 명령의 `--root` 값과 환경 변수 `GHOST_ALICE_SESSION_INTENT_ROOT`를 문자열로 비교합니다. Windows에서 설치기는 `--root`를 슬래시(`C:/...`)로 쓰고, 바인딩은 역슬래시(`C:\...`)로 보관합니다. O12(doctor 오류)와 같은 유형입니다. 실제로 이 차이 때문인지는 수정 후 재현으로 확인해야 합니다.
- 영향: 입력이 원장에 기록되지 않습니다. 대화에 세션 정보(`[session-intent-receipt]`)가 들어오지 않아, 응답 경로 등록과 검토 기록도 하지 못합니다. 11-23의 이 분석 대화도 원장 기록 없이 진행했습니다.
- 앞선 결론에 미치는 영향: [metrics/rerun-2026-11-16-main.md](../metrics/rerun-2026-11-16-main.md)의 "일상 질문 켬: 차단 0.44 → 0.00"은 이 상태에서 잰 값입니다(그 실행의 원장 상태 칸이 모두 비어 있었습니다). main 계열의 Stop 규칙이 바뀐 것은 코드로 확인했지만, 측정값 자체는 입력 기록이 꺼진 상태의 값이라 개선 폭의 근거로 쓸 수 없습니다. O13을 고친 뒤 다시 재야 합니다.
- doctor는 11-16 15:18 재설치 직후 `overall: ok`를 보고했습니다. 첫 거부(15:07)보다 뒤입니다(O3과 같은 유형: 기록이 안 되는 상태를 doctor가 잡지 못함).
