# Ghost-ALICE OS & Autopilot 실사용 개선 프로젝트 기획서

Nov 12, 2026 · @우디

## 개요

Ghost-ALICE OS와 Autopilot을 실제 개발 업무에 쓰면서, Agent의 답변이 부족하거나 틀릴 때 그 원인을 찾아 재현 가능한 GitHub 이슈로 만드는 프로젝트입니다. 새 Agent나 데모를 만드는 것이 아니라, 이미 있는 프레임워크를 일반 사용자가 쓸 수 있는 수준으로 끌어올리는 것이 목적입니다.

- **한 줄 요약:** Agent 거버넌스 프레임워크를 Claude Code·Codex에서 직접 사용하며, 답변 품질을 떨어뜨리는 재현 가능한 오류와 구조적 비효율을 찾아 이슈로 만드는 오픈소스 기여 프로젝트
- **대상:** [AidALL/ghost-alice](https://github.com/AidALL/ghost-alice)(본체), [AidALL/ghost-alice-autopilot](https://github.com/AidALL/ghost-alice-autopilot)(공식 애드온)
- **배경:** 두 프로그램은 Agent의 의도, 작업 범위, 승인, 완료 조건을 관리합니다. 하지만 설치·호환성 오류와 훅 동작 문제 때문에 일반 사용자가 바로 쓰기 어렵습니다. 우리 팀도 설치 과정에서만 실제 문제 4건을 만났습니다.
- **과제 정의서와의 관계:** 에이드올 과제 정의서(v4)의 "Ghost-ALICE와 Autopilot의 문제를 발견한 경우" 항목과 우선 조사 트랙을 주 과제로 삼습니다.

## 문제 정의

핵심 질문은 하나입니다. **Ghost-ALICE가 설치된 환경에서 Agent 답변이 부족하거나 틀릴 때, 어떤 경우에 공통적으로 발생하고 어떻게 고칠 수 있는가?** 아래 가설은 지금까지의 관찰과 코드를 바탕으로 세운 출발점이며, 모두 재현으로 확인해야 합니다.

| 문제 유형 | 사용자가 보는 증상 | 의심 원인(가설) | 근거 수준 |
| --- | --- | --- | --- |
| A. 거버넌스가 조용히 꺼짐 | 의도·범위 관리가 적용되지 않은 답변 | 훅이 거부되어도 사용자에게 보이지 않음 | 확인됨: Windows 경로 표기 차이로 session-intent·Autopilot 훅 거부 |
| B. 이전 의도 재사용 | 바뀐 요청에 예전 목표로 답함 | session-intent 원장이 갱신되지 않거나 잘못 비교됨 | 미확인 |
| C. 완료 판정 오류 | 검증 없이 완료라고 하거나, 정상 답변이 막힘 | Stop 훅의 완료 검사 규칙 | 일부 단서: Windows에서 Stop 훅 테스트 다수 실패 |
| D. 안내 메시지 과다 | 답변이 거버넌스 안내로 채워져 본론이 부족 | 사용자 시스템 메시지 노출 수준(visibility) | 미확인 (트랙 ①) |
| E. 반복 검증 루프 | 같은 확인을 반복하며 시간·토큰 소모 | 원장 비교·해시 검증 반복 | 미확인 (트랙 ③) |

A는 이미 확인된 유형입니다. 훅이 거부되면 Agent는 거버넌스 없이 답하지만, 사용자는 그 사실을 doctor를 돌려야만 알 수 있습니다.

## 목표와 범위

목표는 답변 품질을 떨어뜨리는 문제를 유형별로 묶고, 재현 가능한 것만 이슈로 남기는 것입니다. 범위를 좁게 잡아, 많이 찾기보다 확실하게 재현되는 것을 남깁니다.

| 하는 것 | 하지 않는 것 |
| --- | --- |
| 본체와 Autopilot을 함께 설치해 실제 개발 작업에 사용 | 새 Agent나 데모 앱 개발 |
| 답변이 부족하거나 틀린 사례를 기록하고 유형(A\~E)으로 분류 | 모델 자체의 지식 오류 분석 |
| 깨끗한 환경에서 재현되는 문제만 GitHub 이슈로 등록 | 재현되지 않는 추측성 이슈 등록 |
| 후반부에 수정 코드, 회귀 테스트, PR 작성 | 설치된 skill·Hook 파일을 직접 수정 |

우선 조사 트랙 가운데 \*\*① 사용자 시스템 메시지 노출 수준(중상)\*\*을 주 트랙으로 제안합니다. 답변이 부족하거나 틀리는 문제와 가장 직접 닿아 있기 때문입니다. ③ 반복 검증 루프는 유형 E가 확인되면 보조 트랙으로 다룹니다.

## 수행 방법

모든 사례는 아래 다섯 단계를 거치고, 재현 단계를 통과한 것만 이슈가 됩니다.

1. **설치:** 기준 commit에서 본체와 Autopilot을 함께 설치하고 `install.cmd --doctor` 결과를 저장합니다.
2. **관찰:** 팀원 각자의 실제 개발 작업에 사용하고, 답변이 부족하거나 틀린 순간을 아래 양식으로 기록합니다.
3. **분류:** 사례를 유형 A\~E로 묶고, 같은 유형이 반복되는 조건(운영체제, 플랫폼, 작업 종류)을 찾습니다.
4. **재현:** 새 사용자 계정이나 깨끗한 환경에서 같은 절차로 다시 발생시킵니다. 두 명 이상이 확인해야 통과합니다.
5. **이슈 등록:** 환경, 재현 절차, 기대 동작, 실제 동작, 비식별 증거를 담아 팀 fork에 먼저 등록하고, 묶어서 AidALL에 제출합니다.

관찰 기록 양식입니다. 한 사례당 한 줄씩 추가합니다.

| 날짜 | 기록자 | 환경(OS·플랫폼) | 질문·작업 | 기대한 답변 | 실제 답변 | 유형 | 재현 여부 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| (예시) 11-11 | 우디 | Windows 11 · Claude Code | 설치 후 doctor 점검 | overall: ok | session-intent 훅 거부, overall: error | A | 재현됨 |

증거로는 doctor 출력, 훅 거부 메시지, 세션 로그 일부를 씁니다. 경로의 사용자 이름과 토큰은 지운 뒤 첨부합니다.

## 일정

전반부는 이슈 발굴, 후반부는 수정과 PR입니다. 실제 날짜는 해커톤 일정이 정해지면 채웁니다.

| 단계 | 기간 | 할 일 | 끝났다는 기준 |
| --- | --- | --- | --- |
| 전반부 1 | 1주차 초 | 기준 commit 설치, 팀원별 환경 기록 | 팀원 전원 doctor 결과 저장 |
| 전반부 2 | 1주차 | 실사용과 관찰 기록, 유형 분류 | 관찰 사례 표 작성 |
| 전반부 3 | 1주차 말 | 깨끗한 환경 재현, 이슈 등록 | 재현된 이슈만 fork에 등록 |
| 후반부 | 2주차 | 수정 코드, 회귀 테스트, PR | 수정 전후 테스트 비교, AidALL에 PR 제출 |

## 산출물과 성공 기준

제출물의 중심은 보고서가 아니라 GitHub 이슈와 코드입니다. 보고서는 이슈를 묶어 설명하는 보조 자료입니다.

| 산출물 | 성공 기준 |
| --- | --- |
| 재현 가능한 GitHub 이슈 | 3건 이상, 각 이슈에 재현 절차와 비식별 증거 포함 |
| 답변 품질 문제 유형 분석 | 유형별 발생 조건과 개선 방향을 한 표로 정리 |
| 관찰 기록 표 | 팀원 전원의 실사용 사례 포함 |
| 수정 코드와 회귀 테스트(후반부) | 수정 전 실패하고 수정 후 통과하는 테스트, 기존 테스트 새 실패 0건 |
| AidALL PR(후반부) | 핵심 이슈 기준 1건 이상 제출 |
| Autopilot 실사용 기록 | 승인된 실행 1건 이상에서 작업 종료와 재개 확인 |

이슈 수 목표(3건)는 제안값입니다. 다만 재현되지 않는 것을 채워 넣어 숫자를 맞추지는 않습니다.

## 지켜야 할 규칙과 리스크

규칙

- PPT·보고서·목업만 제출하지 않고, 반드시 이슈와 코드를 함께 냅니다.
- 재현되지 않은 추측은 이슈로 등록하지 않고 관찰 기록에만 남깁니다.
- 본체와 Autopilot을 항상 함께 설치해 사용합니다.
- 이슈에는 민감 정보를 넣지 않습니다. 토큰, 이메일, 사용자 이름이 들어간 경로, 개인 프로젝트 내용이 포함됩니다.
- 설치된 skill·Hook 파일은 직접 고치지 않습니다. 수정은 fork 브랜치에서 하고 설치기로 다시 설치합니다.

리스크

| 리스크 | 대응 |
| --- | --- |
| Autopilot이 최신 Core(main)에 설치되지 않음 | 기준 commit을 Core `v0.5.1` 태그로 두고, 이 문제를 첫 핵심 이슈로 등록 |
| 팀원마다 OS가 달라 재현 결과가 갈림 | 환경을 기록 양식에 필수로 적고, OS별로 따로 재현 |
| 답변 품질 문제가 모델 탓인지 프레임워크 탓인지 구분하기 어려움 | 같은 작업을 Ghost-ALICE 없이도 실행해 비교하고, 차이가 나는 것만 다룸 |
| 트랙 ③ 난이도(최상) | 유형 E가 재현될 때만 보조 트랙으로 착수 |

## 현재까지 진행 상황

Windows 환경에서 설치하는 과정만으로 핵심 이슈 2건과 부차 이슈 2건을 찾았습니다. 자세한 내용은 [Ghost-ALICE 개선 보고서](https://claude.ai/artifact/FmfV2fCCRUTw9rFE3myCNZ)에 있습니다.

| 항목 | 유형 | 상태 |
| --- | --- | --- |
| Windows 경로 비교 오류(session-intent·Autopilot 어댑터 훅 거부) | A | 수정·테스트 완료, PR 대기 |
| Autopilot과 Core 버전 불일치 | 설치·호환성 | 이슈 초안 작성 |
| 빈 스냅샷으로 인한 병합 오탐 | 설치 | 재설치에서 재현 안 됨 |
| Windows 테스트 실패 22건(Stop 훅 등) | C 후보 | 분석 필요 |

환경과 저장소

- 확인 환경: Windows 11, Python 3.14, Claude Code, Core `v0.5.1` + Autopilot 0.5.1
- 팀 저장소: [bogop8-star/ghost-alice](https://github.com/bogop8-star/ghost-alice)(공개 fork)
- 아직 안 한 것: Codex 환경 설치, macOS·Linux 재현, Autopilot 승인 실행 실사용
