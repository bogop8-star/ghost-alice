## I1. `claude -p` 입력이 원장에서 `pending-native-origin`으로 남음

- 환경: Windows 11 · Claude Code CLI 2.1.321 · Core `fix/native-intake-reconcile`
- 재현: [repro/o1/README.md](../repro/o1/README.md)의 `repro_o1.py` 실행
- 실제: 20/20, 재현 스크립트 2/2, 일상 질문 켬 6/6에서 원장 `intake_status`가 `pending-native-origin`으로 남고 이벤트는 `native-input-staged` 1건뿐. 목표·응답 경로 0건. 데스크톱 대화형 대조군은 `observed`
- 기대: 비대화형 입력도 사람 입력으로 확정되거나, 확정할 수 없다면 doctor와 첫 훅 출력이 그 상태를 경고(O3: 같은 시점 doctor `overall: ok`)
- 증거: [evidence/o1-*.json](../evidence/), [daily-test 요약](../daily-test/results/20261112-214258-summary.md)

## I2. 응답 경로 없이 끝난 답이 Stop 차단 후 기록 실패 설명으로 바뀜

- 환경: `claude -p`(O6)와 데스크톱 대화형(O7) 모두
- 재현: Ghost-ALICE를 켠 상태에서 도구를 한 번 이상 쓰는 질문(예: D03 "내일 서울 날씨 어때?")을 경로 등록 없이 답하게 함
- 실제: Stop 훅 `route-unavailable` 차단 → 어시스턴트가 등록을 시도하지만 `claude -p`에서는 등록 명령이 권한 거부 → 마지막 메시지(기록 실패 설명)가 최종 답이 됨. 켬 4/4 실패, 끔 3/3 정상. 대화형에서는 추가 턴과 도구 호출 4회가 생김
- 기대: 사용자에게 가는 답 내용은 바뀌지 않음. 방안 후보:
  1. UserPromptSubmit 또는 첫 PreToolUse 시점에 읽기 전용·설명 턴의 경로를 훅이 자동 등록
  2. 등록에 필요한 명령(원장 읽기, `response_route.py`)을 첫 훅 출력에 정확한 경로와 함께 제시. 지금은 `_shared/session_intent_ledger.py`가 아니라 `session-intent-analyzer/scripts/`에 있어 찾느라 호출이 늘어남
  3. `claude -p`처럼 추가 턴에서 등록할 수 없는 환경이면 차단 대신 경고로 낮춤
- 증거: [daily-test 반복 실행](../daily-test/results/20261113-D03-rerun-summary.md), [11-16 증거 E1](../evidence/session-2026-11-16-desktop.md#e1-읽기-전용-요약-턴에서-stop-훅-route-unavailable-o7)

## I3. 훅 기록에 차단 결정이 남지 않아 모니터가 차단을 성공으로 표시

- 배경: Claude Code의 Stop 훅은 종료 코드 0과 JSON `decision: "block"`으로 차단합니다. 종료 코드 0은 정상 동작입니다.
- 실제: `~/.ghost-alice/session-logs/claude/<session>/strict-hook-output.jsonl`(schema `strict-hook-output.v1`)의 필드는 `exit_code`, `stdout`, `visible_decision` 등입니다. `visible_decision`은 표시 결정(예: `force_show`)일 뿐이고, 게이트 결정 `block`과 사유 코드(`route-unavailable`)는 `stdout` JSON 문자열 안에만 있습니다(11-16 세션 Stop 행 확인). 외부 도구가 stdout을 다시 해석해야 합니다. hook-monitor는 처음에 차단을 "성공"으로 표시했고, 030fc8ad 세션 분석에서 차단 10회가 모두 exit 0으로 기록됨(분석 보고서: hook-monitor `captures/analysis/030fc8ad-…-blocked-turns-20261113.md`, 저장소 밖)
- 기대: 훅 실행 기록에 `decision`과 `reason`(예: `route-unavailable`, `criterion-unbound`)을 구조화된 필드로 남김. 출력 원문은 계속 제외
- 재현: Stop 차단이 나는 턴을 만든 뒤 `~/.ghost-alice/strict-hook-output.jsonl`의 해당 행을 확인

## I4. 작업 뒤 등록하면 Autopilot 기록이 `time-invalid`로 영구 실패

- 실제(11-13): 작업을 먼저 하고 작업 단위·기준·경로를 나중에 등록한 AC1·RT1~3은 Stop에서 `time-invalid`(Verification must follow ORIGINAL capture)로 기록 실패, 원장 unmet 유지. 등록을 먼저 한 PS1은 `applied`. 규칙상 같은 작업을 다시 하거나 시각을 고쳐 맞출 수 없어 기록이 영구히 남지 않음
- 11-16 확인: 작업 전에 등록하자 다음 도구 호출에서 바로 `completion-preflight: prepared` 통지([증거 E4](../evidence/session-2026-11-16-desktop.md#e4-작업-전-등록-순서-r3-e-확인))
- 기대: 실행 기준 없이 쓰기 도구(Edit/Write, git commit/push 등)가 처음 호출될 때 PreToolUse 훅이 "작업 단위가 등록되지 않았다"고 미리 알림. Stop에서 `time-invalid`가 나면 원인(등록이 작업보다 늦음)을 사람이 읽을 수 있게 표시
- 재현: 설명 경로만 등록한 상태에서 파일을 하나 고친 뒤 작업 단위와 기준을 등록하고 턴을 끝냄

## I5. `prepare-response`의 `response-unbound` 오류가 어느 주장인지 알려 주지 않음

- 실제: 주장 11개 중 일부가 답변 원문의 부분 문자열이 아니면 `{"reason": "response-unbound", "detail": "Name each source-backed claim with its exact statement from the explanation draft"}`만 반환
- 기대: `detail` 또는 별도 필드에 일치하지 않은 주장의 번호(`claim_index`)를 담음. 원문은 이미 호출자가 가지고 있으므로 주장 문장을 다시 보여 줄 필요는 없음
- 재현: 답변 파일과, 답변에 없는 문장 하나를 섞은 주장 JSON으로 `completion_assessment.py prepare-response --claims-file` 실행
- 증거: [11-16 증거 E3](../evidence/session-2026-11-16-desktop.md#e3-주장-문장-불일치-시-오류-메시지-o9)

## I6. 설치 체크아웃의 브랜치 전환이 실행 중 skill 본문을 바꿈

- 실제: `~/.claude/skills/<skill>`이 Core 체크아웃 폴더를 가리키는 junction. 체크아웃에서 브랜치를 바꾸면 실행 중 세션이 읽는 skill 본문이 바뀜. 훅은 `~/.ghost-alice/runtime/current`의 복사본을 실행하므로 skill 본문과 훅 코드의 버전이 어긋날 수 있음. 사용자가 "새 브랜치에서 작업하면 내용이 이상해진다"고 보고
- 기대 후보: (1) 설치 문서와 doctor에 "설치에 연결된 체크아웃에서 개발하지 말고 별도 clone이나 worktree를 쓸 것"을 안내 (2) doctor가 체크아웃의 현재 HEAD와 `install-state`의 `source_head`가 다르면 경고 (3) skill도 런타임처럼 복사본으로 설치하는 선택지
- 재현: junction 설치 상태에서 체크아웃 브랜치를 skill 본문이 다른 브랜치로 바꾼 뒤 새 대화에서 해당 skill을 불러 내용 비교
- 증거: [11-16 증거 E5](../evidence/session-2026-11-16-desktop.md#e5-체크아웃-브랜치-전환이-설치된-skill을-바꿈-o10)
